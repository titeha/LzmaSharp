# Заявление о происхождении кода (PROVENANCE)

Версия 1, 2026-07-17. Проект **LzmaSharp** (`Lzma.Core` + приложение `Lzma.Ui`).

Документ описывает происхождение исходного кода, способ его создания, применённые инструменты
разработки и меры контроля качества/корректности. Цель — сделать провенанс **доказуемым на бумаге**
до любых процедур экспертизы или включения в реестр.

---

## 1. Что это за код

LzmaSharp — **самостоятельная управляемая (managed C#) реализация** семейства алгоритмов LZMA/LZMA2,
кодеков PPMd и BCJ/BCJ2, контейнера `.7z`, шифрования 7zAES и исследовательской ГОСТ-ветки.

Существенные свойства:
- **100% managed**, без `unsafe`, без P/Invoke, без нативных библиотек;
- **нет сторонних codec-зависимостей** в production-сборке — единственная зависимость времени
  выполнения — стандартная библиотека .NET (см. `THIRD_PARTY_NOTICES.md`);
- совместимость с настоящим 7-Zip подтверждена (чтение и запись, включая AES и многотомные архивы).

Редакции (см. дорожную карту проекта):
- **Community** — открытое ядро под лицензией **MIT**, публикуется на NuGet; ГОСТ-ветка — как
  исследовательская, **без каких-либо заявлений о защите информации**;
- **Gov** — редакция для госсектора: криптография через сертифицированный криптопровайдер
  (встраивание), возможна отдельная проприетарная сборка; проектируется отдельно.

## 2. Как получен каждый компонент

Полная таблица «компонент → источник → лицензия → способ переноса» — в `THIRD_PARTY_NOTICES.md`.
Кратко, два способа:

- **Порт с эталона.** LZMA, LZMA2, PPMd (вар. H), фильтры BCJ/BCJ2 и структура контейнера `.7z`
  перенесены с эталонных исходников **LZMA SDK** (Public Domain). Эталон хранится в `vendor/lzma-sdk/`
  с фиксацией версии и SHA-256 (см. `vendor/lzma-sdk/*/README`). Корректность — **побайтовая сверка**
  выхода с настоящими 7-Zip и `xz` на реальных архивах.
- **Реализация по спецификации.** BZip2 (формат BZip2), Deflate/Deflate64 (RFC 1951 и формат Deflate64),
  CRC-32, схема 7zAES (формат 7-Zip; примитивы AES-256/SHA-256 — из .NET BCL), а также ГОСТ-примитивы
  (Кузнечик — ГОСТ Р 34.12-2015/RFC 7801; Магма — RFC 8891; гаммирование — ГОСТ Р 34.13-2015; Стрибог —
  ГОСТ Р 34.11-2012/RFC 6986; HMAC/KDF — RFC 7836) реализованы **по опубликованным стандартам** и
  проверены **официальными тест-векторами**.

Исключительные права на данную реализацию принадлежат автору (Артемий Соболев). Открытая лицензия MIT
исключительных прав не отчуждает и включению в реестр не препятствует; для Gov-редакции при
необходимости готовится отдельная проприетарная сборка.

## 3. Инструменты разработки, включая ИИ (честно и без умолчаний)

Разработка велась человеком-автором с использованием **ИИ-ассистентов программирования** — на раннем
этапе ChatGPT, далее Claude Code — **как инструментов** написания и рефакторинга кода (аналогично роли
IDE, компилятора или анализатора). Ключевые решения по архитектуре, приёмке и корректности принимал и
проверял автор.

Мы **сознательно не скрываем** факт применения ИИ: непрозрачность происхождения — именно то, что
осложняет экспертизу. Риск «сгенерированного кода» компенсируется проверяемыми мерами:

- **Эталонная сверка.** Выход кодеков сверяется побайтово с настоящими 7-Zip / `xz`; эталонные
  исходники (LZMA SDK) хранятся в репозитории.
- **Дифференциальные и round-trip тесты.** Более 1500 юнит- и интеграционных тестов ядра (`xUnit`):
  encode→decode инварианты, сверка с внешним оракулом (BZip2), живой интероп с настоящим 7-Zip
  (тесты `t`/`e` с паролем для AES), официальные тест-векторы для ГОСТ (RFC 6986/7801/7836/8891).
- **Ручное ревью** каждого шага; изменения вносились малыми проверяемыми коммитами.
- **Сохранённая история.** Коммиты не «схлопываются» (без squash), поэтому эволюция кода прослеживается;
  релизные теги подписываются.

Иными словами, доверие обеспечивается **не происхождением строки кода, а воспроизводимой проверкой её
поведения** относительно опубликованных эталонов и стандартов.

## 4. Воспроизводимость и цепочка сборки

- Версия .NET SDK зафиксирована в `global.json`.
- Зеркало исходного кода в РФ — **GitFlic** (`gitflic.ru/titeha/lzmasharp`), синхронизируется с GitHub.
- План (см. дорожную карту): сборка релизов на инфраструктуре в РФ (self-hosted runner / GitFlic CI) с
  локальным кэшем зависимостей; генерация SBOM (CycloneDX) в CI и приложение к каждому релизу.

## 5. Чем этот код НЕ является

- ГОСТ-ветка — **исследовательская** собственная реализация; это **не сертифицированное СКЗИ** и не
  несёт заявлений о соответствии требованиям к средствам криптографической защиты информации. Для
  госсектора криптография планируется через сертифицированный криптопровайдер (Gov-редакция).
- Практики безопасной разработки (сверка, валидация путей извлечения, план фаззинга, лимиты против
  zip-bomb) описаны в `docs/SDL.md`; часть из них — **действующие**, часть — **план** (помечено явно,
  без выдачи планов за готовое).
