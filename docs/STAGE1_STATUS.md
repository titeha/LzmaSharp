# Состояние этапа 1

## Текущий статус

Этап 1 завершён.

Проект доведён до состояния надёжного управляемого декодера / распаковщика 7z для поддерживаемого подмножества формата без AES.

Основная цель этапа 1 — довести управляемый декодер / распаковщик 7z до надёжного состояния для поддерживаемого подмножества формата без AES.

На текущий момент основной объём тестовой стабилизации `SevenZipFolderDecoder` уже выполнен. Новые синтетические тесты дальше добавляются только при наличии конкретного риска, а не ради полного перебора всех искусственных комбинаций.

## Критерий завершения этапа 1

Этап 1 считается завершённым, когда репозиторий явно демонстрирует надёжный управляемый декодер / распаковщик 7z для поддерживаемого подмножества формата без AES.

Это означает, что:

- разбор архива работает для поддерживаемого подмножества;
- декодирование работает для поддерживаемого подмножества;
- безопасность распаковки покрыта тестами;
- для важных поддерживаемых сценариев есть тесты на реальных архивах;
- документация отражает реальное состояние проекта;
- сценарии, связанные с AES, явно остаются вне области этапа 1 и перенесены в этап 1.5.

## Что уже есть

### Основные компоненты

- `SevenZipArchiveReader`;
- `SevenZipArchiveDecoder`;
- `SevenZipEncodedHeaderDecoder`;
- `SevenZipFolderDecoder`;
- вспомогательные части распаковки и модели декодированных файлов.

### Тестовая база

В зоне `SevenZip` есть большая группа тестов на синтетических сценариях и реальных архивах.

Покрыты:

- чтение структуры архива;
- encoded header;
- FilesInfo;
- StreamsInfo;
- PackInfo;
- SubStreamsInfo;
- CRC;
- split / solid-сценарии;
- single-file и multi-file сценарии;
- empty file / empty directory / empty streams;
- ошибки формата и недостаток входных данных;
- безопасность распаковки на диск;
- явно неподдерживаемые AES-сценарии.

### Поддерживаемые методы 7z, присутствующие в коде

- `Copy`;
- `LZMA`;
- `LZMA2`;
- `Delta`;
- `Swap2`;
- `Swap4`;
- BCJ-фильтры:
  - `x86`;
  - `ARM`;
  - `ARMT`;
  - `ARM64`;
  - `PPC`;
  - `SPARC`;
  - `IA64`;
- `BCJ2`;
- `BZip2`;
- `PPMd`;
- `Deflate`;
- `Deflate64`.

### Безопасность и устойчивость

Тестами уже закреплены важные сценарии безопасности и устойчивости:

- небезопасные пути;
- абсолютные пути из архива;
- попытки выхода за пределы целевой директории;
- дублирующиеся пути вывода;
- зарезервированные имена Windows;
- недопустимые символы пути;
- конфликт файлов и директорий;
- коллизии по регистру;
- некорректные времена файлов;
- сценарии, связанные с CRC;
- пустые потоки и подпотоки;
- некорректные topology-сценарии folder-а;
- неконсистентные размеры потоков;
- неподдерживаемые, но явно распознанные сценарии.

## Текущее состояние покрытия SevenZipFolderDecoder

`SevenZipFolderDecoder` покрыт прямыми тестами по основным поддерживаемым веткам.

Покрыты одиночные coder-сценарии:

- `Copy`;
- `LZMA`;
- `LZMA2`;
- `Delta`;
- `Swap2`;
- `Swap4`;
- BCJ-фильтры;
- `BZip2`;
- `PPMd`;
- `Deflate`;
- `Deflate64`;
- неизвестные / неподдерживаемые coder-ы.

Покрыты BCJ2-сценарии:

- подготовка входных потоков;
- producer coder-ы;
- topology-проверки;
- size-limit проверки;
- malformed-stream проверки;
- выбор финального выхода;
- merge через `TryDecodeBcj2ToArray`;
- ветки `E8`, `E9`, `Jcc`;
- граничные случаи `disp32` и `rel32`.

Покрыты общие сценарии folder decoder:

- линейная topology folder-а;
- некорректные `BindPair`;
- некорректные размеры входных и выходных потоков;
- выбор `pack stream` для одного и нескольких folder-ов;
- проверки `PackInfo`;
- проверки `UnpackInfo`;
- проверки `FolderUnpackSizes`;
- проверки `PackSizes`;
- проверки `PackPos`;
- negative-path для недопустимых свойств coder-ов;
- negative-path для неконсистентных размеров.

Новые синтетические тесты для `SevenZipFolderDecoder` дальше добавляются только при обнаружении конкретного незакрытого риска, а не ради полного перебора всех комбинаций.

## Что явно не входит в этап 1

- AES-шифрованные архивы;
- зашифрованные заголовки;
- production-ready энкодер;
- тяжёлая оптимизация;
- приложение / UI;
- собственные реализации временно внешних codec-веток.

## AES после этапа 1

AES и зашифрованные заголовки вынесены в этап 1.5.

Этап 1.5 должен быть отдельным расширением уже стабилизированного декодера / распаковщика, а не условием закрытия этапа 1.

Для этапа 1.5 нужно будет отдельно закрыть:

- распознавание AES coder-а;
- разбор свойств AES coder-а;
- API для передачи пароля;
- derivation ключа по правилам 7z AES;
- расшифровку packed stream-ов перед обычным декодированием;
- зашифрованные заголовки, если они нужны для реальных архивов;
- тесты на реальные AES-архивы;
- negative-тесты на отсутствующий пароль, неверный пароль и повреждённые данные;
- проверку, что ошибки AES не приводят к небезопасной записи на диск.

На этапе 1 AES-сценарии должны оставаться явно неподдерживаемыми и возвращать согласованный результат, а не падать случайными исключениями.

## Временные внешние зависимости

На этапе 1 допускаются узкие управляемые зависимости для отдельных методов 7z, чтобы закрывать реальные сценарии декодирования маленькими проверяемыми шагами.

Текущие временные зависимости:

- `SharpZipLib` для декодирования `BZip2`;
- `SharpCompress` для отдельных методов 7z, например `PPMd` и `Deflate64`.

Долгосрочный план:

- заменить временные внешние декодеры собственными реализациями проекта;
- реализовать собственные управляемые версии:
  - `PPMd`;
  - `BZip2`;
  - `Deflate`;
  - `Deflate64`;
- рассмотреть поддержку ZIP-совместимых сценариев;
- при замене сохранять внешний контракт и стабильность тестов.

## Правило для оставшихся тестов этапа 1

Новые тесты добавляются только если они закрывают один из рисков:

- безопасность распаковки;
- crash / exception path;
- публичный контракт результата `Ok` / `InvalidData` / `NotSupported`;
- ветку, которую реально можно сломать при оптимизации или рефакторинге;
- поведение на реальном архиве.

## Итог этапа 1

Этап 1 закрыт после финальной сверки документации и полного зелёного прогона тестов.

Зафиксировано:

- поддерживаемое подмножество 7z без AES декодируется и распаковывается;
- безопасность распаковки покрыта тестами;
- `SevenZipFolderDecoder` покрыт прямыми тестами по основным поддерживаемым веткам;
- реальные архивы используются для проверки совместимости;
- AES и зашифрованные заголовки явно вынесены в этап 1.5;
- временные внешние codec-зависимости описаны как осознанное промежуточное решение;
- дальнейшая работа переносится к этапу 1.5 / этапу 2 согласно `ROADMAP.md`.
