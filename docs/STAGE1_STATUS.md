# Состояние этапа 1 — декодер / распаковка 7z без AES

Этап 1 завершён. Это авторитетный документ о состоянии decoder-path. Карта этапов — в
[`ROADMAP.md`](ROADMAP.md).

Проект доведён до состояния надёжного управляемого декодера / распаковщика 7z для
поддерживаемого подмножества формата без AES.

## Что реализовано

### Основные компоненты

- `SevenZipArchiveReader`;
- `SevenZipArchiveDecoder`;
- `SevenZipEncodedHeaderDecoder`;
- `SevenZipFolderDecoder`;
- вспомогательные части распаковки и модели декодированных файлов.

### Поддерживаемые методы и фильтры

`Copy`, `LZMA`, `LZMA2`, `Delta`, `Swap2`, `Swap4`, BCJ-фильтры (`x86`, `ARM`, `ARMT`,
`ARM64`, `PPC`, `SPARC`, `IA64`), `BCJ2`, `BZip2`, `PPMd`, `Deflate`, `Deflate64`.

### Безопасность распаковки

Тестами закреплены ключевые сценарии: небезопасные и абсолютные пути, выход за пределы
целевой директории, дублирующиеся пути, зарезервированные имена Windows, недопустимые
символы, конфликт файлов и директорий, коллизии по регистру, некорректные времена файлов.

## Тестовое покрытие

Покрытие — на уровне unit-, интеграционных и real-archive тестов. Источник правды по
конкретным тестам — код в `tests/Lzma.Core.Tests/SevenZip`. Сводка по группам:

- чтение структуры архива, encoded header, `StreamsInfo` / `FilesInfo` / `PackInfo` /
  `SubStreamsInfo`, CRC;
- split / solid, single-file / multi-file, empty file / directory / streams;
- ошибки формата и недостаток входных данных;
- безопасность распаковки на диск;
- `SevenZipFolderDecoder` — одиночные coder-сценарии по всем поддерживаемым веткам,
  BCJ2 (подготовка потоков, topology, size-limit, malformed, ветки `E8`/`E9`/`Jcc`,
  граничные `disp32`/`rel32`), общие сценарии folder decoder (topology, `BindPair`,
  размеры, выбор pack stream, negative-path);
- реальные `.7z`-архивы для важных методов и комбинаций фильтров;
- явно неподдерживаемые сценарии (AES и пр.), возвращающие согласованный результат вместо
  случайных исключений.

Основной объём тестовой стабилизации `SevenZipFolderDecoder` выполнен. Новые synthetic-тесты
дальше добавляются только при наличии конкретного незакрытого риска.

## Что не входило в этап 1

- AES-шифрованные архивы и зашифрованные заголовки (вынесены в этап 1.5);
- production-ready энкодер (этап 2);
- тяжёлая оптимизация и UI;
- собственные реализации временно внешних codec-веток.

## Временные внешние зависимости

На этапе 1 были допущены узкие управляемые зависимости. К текущему моменту (этап 2) все
codec-методы (`Deflate`/`Deflate64`, `BZip2`, `PPMd`) переведены на собственные декодеры
**и энкодеры** (плюс ZIP-контейнер `ZipReader`/`ZipWriter`), а `SharpZipLib` и `SharpCompress`
удалены из production — внешних codec-зависимостей больше нет (см. этап 2 в [`ROADMAP.md`](ROADMAP.md)).

## Итог

- поддерживаемое подмножество 7z без AES декодируется и распаковывается;
- безопасность распаковки покрыта тестами;
- `SevenZipFolderDecoder` покрыт прямыми тестами по основным веткам;
- реальные архивы используются для проверки совместимости;
- AES и зашифрованные заголовки вынесены в этап 1.5;
- временные внешние codec-зависимости описаны как осознанное промежуточное решение.
