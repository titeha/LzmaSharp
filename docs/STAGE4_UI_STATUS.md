# Статус этапа 4 (UI) — кросс-платформенный интерфейс архиватора

Этап 4 — прикладной слой (CLI и UI) поверх стабильного ядра `Lzma.Core`. Этот документ
описывает **UI-часть**. Статус: **в работе** (десктоп: чтение/просмотр, извлечение и
**потоковое создание/извлечение архивов больше 2 ГиБ** с настройками сжатия и прогрессом).

## Выбор технологии: Avalonia

UI делается на **Avalonia UI** одним общим MVVM-кодом на все платформы.

Почему Avalonia, а не альтернативы:

- **WPF** — только Windows (не подходит: нужны Linux/Android/Apple).
- **MAUI** — нет десктопного Linux.
- **Avalonia** — Windows/Linux/macOS/Android/iOS из одного кода; XAML, привязки и стили
  максимально близки к WPF; MVVM-философия.

Козырь проекта: ядро `Lzma.Core` — чистый managed C# без `unsafe`, поэтому кодеки и вся
ГОСТ-крипта уже работают везде, где есть .NET. UI на Avalonia делает приложение
по-настоящему «одним на всех».

## Архитектура

- Проект `src/Lzma.Ui` — Avalonia 12, `net10.0`, Fluent-тема, compiled bindings.
- MVVM на собственном пакете пользователя **`Ti-Soft.MvvmUtilites`** (`ObservableObject`,
  `RelayCommand`/`AsyncRelayCommand`; `netstandard2.0`/`net8.0` — кросс-платформенно).
- **Логика — за швами, тестируема без UI/IO:** платформенные операции скрыты за
  абстракциями `IArchivePicker` (файловый диалог) и `IPasswordPrompt` (запрос пароля);
  Avalonia-реализации (`AvaloniaArchivePicker`, `AvaloniaPasswordPrompt`) внедряются в
  `MainViewModel` в `App.axaml.cs`.
- Навигация по архиву строится в `MainViewModel` как виртуальное дерево из путей записей
  (папки выводятся даже без явных записей-каталогов).
- Тесты — `tests/Lzma.Ui.Tests` (через `InternalsVisibleTo`), VM проверяется со стабами.

### Замечание про будущее разделение проектов

Пока всё в одном проекте `Lzma.Ui` (десктоп). Когда дойдём до мобильных платформ, его
разделим на общий `Lzma.Ui` (VM/View/сервисные интерфейсы) и тонкие платформенные головы
(`Lzma.Ui.Desktop`, `Lzma.Ui.Android`, `Lzma.Ui.iOS`). VM/Views уже свободны от
платформенных зависимостей, поэтому это будет механический рефакторинг.

## Реализовано (v1 — чтение/просмотр)

1. **Каркас** Avalonia-приложения, ссылка на `Lzma.Core`, пустое окно.
2. **MVVM-фундамент**: `MainViewModel`, динамический заголовок через привязку.
3. **Открытие архива**: тулбар «Открыть…», файловый диалог за `IArchivePicker`,
   `DecodeToEntries` в фоне (`Task.Run`), обработка `Ok`/`NotSupported`/`InvalidData`.
4. **Браузер**: таблица содержимого (значок/имя/размер/тип) + навигация по папкам
   (вход двойным кликом, «Вверх», текущий путь).
5. **Пароль**: модальный диалог `PasswordWindow` + `IPasswordPrompt`; открытие
   зашифрованных архивов (**AES и ГОСТ** — расшифровка определяется автоматически по
   архиву), повтор при неверном пароле, отмена.
6. **Извлечение на диск**: кнопка «Извлечь всё…», выбор папки через `IFolderPicker`,
   `ExtractToDirectory` в фоне (`IsBusy` + индикатор), с паролем (если был при открытии).
   VM хранит байты архива и пароль до закрытия для распаковки без повторного открытия.
7. **Создание архива**: кнопки «Создать…» (выбор файлов через `ISourceFilesPicker`) и
   «Создать из папки…» (рекурсивный обход через `ISourceFolderPicker`, относительные имена
   записей строит `ArchiveEntryNaming`) + выбор метода (LZMA2/PPMd/Auto/Copy), путь сохранения
   через `ISaveFilePicker`, сборка `SevenZipArchiveWriter.BuildArchive` и запись на диск в фоне.
   Шифрование (AES/ГОСТ) при создании пока не входит — нужен выбор движка и AES-на-запись в ядре.
8. **Отложенный индикатор занятости**: индикатор показывается только если операция длится
   дольше порога (по умолчанию 3 с) — быстрые операции его не показывают. Повторный запуск
   во время операции заблокирован (`IsOperating`).

### Шов операций над архивом

Операции открытия/извлечения/создания вынесены за интерфейс **`IArchiveService`**
(реализация `LzmaArchiveService` поверх `Lzma.Core`): `OpenAsync`, `ExtractAllAsync`,
`CreateArchiveAsync`, `WriteArchiveAsync`, `DescribeMethodsAsync`. Вся фоновая раскладка
(`Task.Run`) и работа с паролем — в сервисе; `MainViewModel` от прямых вызовов ядра
освобождён. Это шов, к которому подключаются новые возможности (прогресс, шифрование при
создании), не размазывая логику по модели представления.

Покрытие: 47 тестов (`MainViewModel` — открытие/навигация/пароль/извлечение/создание из
файлов и папок/отложенный индикатор + `LzmaArchiveService` — round-trip создания на всех
методах + `ArchiveEntryNaming` — построение имён записей), в т.ч. сквозные пути через AES-
и ГОСТ-архивы и запись создаваемого архива на диск. **Avalonia-пикеры и XAML-обвязка
автотестами не покрыты** — проверяются живым запуском.

## Реализовано (v2 — потоковый пайплайн больших файлов, настройки, прогресс)

Ключевой сдвиг: и создание, и извлечение больше **не грузят файл/архив в память целиком** —
работают потоком через `Stream` с размерами `long`/`ulong` и буферами из `ArrayPool`.
Триггером стала ошибка «Stream was too long» на 2-ГиБ образе диска; теперь поддерживаются
архивы **> 2 ГиБ** из конца в конец (боевой прогон ФИАС: 55 ГиБ → 330 ГиБ распаковки, сжатие
LZMA обратно в ~53 ГиБ без падений).

1. **Потоковое создание** (`SevenZipArchiveWriter.Build*ArchiveToStream` → сервис
   `CreateArchiveToFileAsync`, пишет прямо в целевой файл):
   - **LZMA2 — многопоточно:** мелкие файлы (≤ размер блока) сжимаются параллельно волнами и
     пишутся строго по порядку; большие — блочно-параллельно с внутри-файловым параллелизмом.
     Результат **байт-в-байт** совпадает с последовательным.
   - **PPMd / Copy — пофайлово потоком** (PPMd строго последователен по своей природе).
   - **«Авто» — пофайловый автовыбор кодека** по содержимому (сэмпл ≤ 1 МиБ, гистограмма +
     энтропия Шеннона): текст → **PPMd** (плотнее), несжимаемое/уже-сжатое (энтропия ≥ 7.7
     бит/байт: медиа, шифр, случайное) → **Copy** (адаптивный store, не тратим CPU), иначе →
     **LZMA2**. У каждого файла — свой coder (per-folder `coderBytes` в next-header). Смешанные
     кодеки в одном архиве **проверены чтением настоящим 7-Zip** — читает без ошибок.
2. **Настройки сжатия в UI:** число потоков (`0` = авто/все ядра; меньше — система отзывчивее) и
   размер словаря LZMA2 — пробрасываются из VM в `CreateArchiveToFileAsync`.
3. **Потоковое извлечение с диска** (`ExtractToDirectoryFromStream` → `ExtractArchiveFileAsync`):
   архив читается из файла потоком, не грузясь в память. Извлечение **атомарно** (при ошибке —
   откат созданных файлов/каталогов), с проверкой CRC и валидацией путей вывода. Внутри LZMA2-
   folder-а — гранулярность прогресса по chunk-ам (обход невозможности LZMA1 возобновлять
   частичный ввод — chunk-framing: декодеру скармливаются целые chunk-и).
4. **Обзор большого архива без распаковки** (`ListEntriesFromStream` → `OpenFromFileAsync`):
   читает только структуру (сигнатуру + next-header) и показывает дерево, не декодируя данные.
5. **Определённый прогресс:** проценты + живой счётчик «X / Y МБ» + **ETA** + **отмена**
   (`CancellationToken`, гранулярно — по chunk-ам/файлам/волнам). Есть живой счётчик и на фазе
   сканирования исходных файлов.
6. **Показ текущего файла** (как в 7-Zip): при создании — «Сжатие [PPMd]: имя» (с меткой
   выбранного кодека), при извлечении — «Извлечение: имя». Для «Авто» в **итоговую сводку**
   ложится разбивка «Авто: PPMd — 12, LZMA2 — 40, Copy — 8» (счётчики набираются синхронно —
   точны к завершению операции).
7. **Раскладка окна:** прогресс-блок (градусник/проценты/счётчик/ETA/текущий файл/отмена) вынесен
   из тулбара в нижнюю панель над строкой статуса (`WrapPanel` — длинное имя переносится, не
   уезжает за край); панель скрыта, когда нет ни операции, ни статуса.

Новые методы шва `IArchiveService`: `CreateArchiveToFileAsync`, `ExtractArchiveFileAsync`,
`OpenFromFileAsync` (+ каналы `IProgress<SevenZipCompressionFileProgress>` / `IProgress<string>`
для «текущего файла»). Пикеры путей — `ISaveFilePicker`, `PickArchivePathAsync` (путь без чтения).

Покрытие UI-тестами выросло до **107** (потоковое создание/настройки/видимость нижней панели/
разбивка кодеков и т. д.); ядро — **1530**. Avalonia-пикеры и XAML по-прежнему проверяются живым
запуском.

## Границы и ограничения

- Извлечение **выделенного** (части файлов) пока не входит — только весь архив. Создание и
  извлечение всего архива есть, в т.ч. потоково для больших файлов (см. раздел v2).
- Два пути чтения: классическое «Открыть…» грузит архив **в память** (`DecodeToEntries`) —
  для зашифрованных/сложных и небольших архивов; «Открыть большой архив…» и «Извлечь архив с
  диска…» идут **потоком** без загрузки в память. Потоковый путь пока не поддерживает
  зашифрованные архивы и `EncodedHeader` — для них остаётся память.
- **Пофайловое сжатие держит один файл в памяти** (PPMd/Copy/Auto и мелкие файлы LZMA2): файл
  `> 2 ГиБ` таким путём пока не берётся (для одного большого файла работает блочно-потоковый
  LZMA2). Залоченный файл (открыт другим процессом) валит всю операцию — грациозный пропуск
  ещё не сделан.
- Сессия не сохраняется (нет «недавних»/«открыть последний») — на будущее.
- Многоколоночный `DataGrid` не используется (пакет несовместим под Avalonia 12) —
  таблица собрана на `ListBox` + строка-заголовок.
- **Пароль vs неподдержка:** `DecodeToEntries` без пароля возвращает один и тот же
  `NotSupported` и для «нужен пароль», и для «неподдерживаемая возможность». Поэтому на
  неподдерживаемом (незашифрованном) архиве UI может зря показать диалог пароля. Различить
  их без доработки ядра нельзя. После принятого пароля `NotSupported` трактуется как
  неподдерживаемая возможность (а не неверный пароль) — сообщение это отражает.
- **AES + BCJ2 не поддерживается ядром:** архивы с `.exe`/бинарниками под AES (7-Zip
  включает фильтр BCJ2) не открываются — см. [`STAGE15_AES_STATUS.md`](STAGE15_AES_STATUS.md).
  Обычные AES+LZMA2 и ГОСТ-архивы открываются штатно.

## Дальше

- Извлечение **выделенного** (части файлов).
- Грациозный пропуск залоченных/недоступных файлов при создании (сейчас один такой файл валит
  всю операцию) + отдельный «отчёт по пропущенным».
- Шифрование **при создании** с выбором движка (ГОСТ/AES), значением по умолчанию и запоминанием
  выбора. Предусловие AES-варианта — AES-шифрование **на запись** в `Lzma.Core` (сейчас на запись
  есть только ГОСТ). Потоковая крипта > 2 ГиБ — отдельная ядровая задача.
- Крупные ядровые хвосты, влияющие на UI: **тома** (разбиение на `.001/.002`), **BCJ2-энкодер**
  (сейчас `.exe` жмётся не так плотно, как у 7-Zip — фильтр только на чтение), потоковая
  запись/чтение AES/BCJ2 > 2 ГиБ.
- Рефактор дублирующегося ядра извлечения (`ExtractToDirectory` span + `...FromStream` — ~370
  общих строк в `ExecuteExtractionCore`); страхуется 46 тест-файлами.
- Позже: мобильные головы (Android/Apple), сохранение сессии («недавние»), бенчмарки крипты.
