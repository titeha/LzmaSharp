# Статус этапа 4 (UI) — кросс-платформенный интерфейс архиватора

Этап 4 — прикладной слой (CLI и UI) поверх стабильного ядра `Lzma.Core`. Этот документ
описывает **UI-часть**. Статус: **в работе** (десктоп, чтение/извлечение).

## Выбор технологии: Avalonia

UI делается на **Avalonia UI** одним общим MVVM-кодом на все платформы.

Почему Avalonia, а не альтернативы:

- **WPF** — только Windows (не подходит: нужны Linux/Android/Apple).
- **MAUI** — нет десктопного Linux.
- **Avalonia** — Windows/Linux/macOS/Android/iOS из одного кода; XAML, привязки и стили
  максимально близки к WPF; MVVM-философия.

Козырь проекта: ядро `Lzma.Core` — чистый managed C# без `unsafe`, поэтому кодеки и вся
ГОСТ-крипта уже работают везде, где есть .NET. UI на Avalonia делает приложение
по-настоящему «одним на всех».

## Архитектура

- Проект `src/Lzma.Ui` — Avalonia 12, `net10.0`, Fluent-тема, compiled bindings.
- MVVM на собственном пакете пользователя **`Ti-Soft.MvvmUtilites`** (`ObservableObject`,
  `RelayCommand`/`AsyncRelayCommand`; `netstandard2.0`/`net8.0` — кросс-платформенно).
- **Логика — за швами, тестируема без UI/IO:** платформенные операции скрыты за
  абстракциями `IArchivePicker` (файловый диалог) и `IPasswordPrompt` (запрос пароля);
  Avalonia-реализации (`AvaloniaArchivePicker`, `AvaloniaPasswordPrompt`) внедряются в
  `MainViewModel` в `App.axaml.cs`.
- Навигация по архиву строится в `MainViewModel` как виртуальное дерево из путей записей
  (папки выводятся даже без явных записей-каталогов).
- Тесты — `tests/Lzma.Ui.Tests` (через `InternalsVisibleTo`), VM проверяется со стабами.

### Замечание про будущее разделение проектов

Пока всё в одном проекте `Lzma.Ui` (десктоп). Когда дойдём до мобильных платформ, его
разделим на общий `Lzma.Ui` (VM/View/сервисные интерфейсы) и тонкие платформенные головы
(`Lzma.Ui.Desktop`, `Lzma.Ui.Android`, `Lzma.Ui.iOS`). VM/Views уже свободны от
платформенных зависимостей, поэтому это будет механический рефакторинг.

## Реализовано (v1 — чтение/просмотр)

1. **Каркас** Avalonia-приложения, ссылка на `Lzma.Core`, пустое окно.
2. **MVVM-фундамент**: `MainViewModel`, динамический заголовок через привязку.
3. **Открытие архива**: тулбар «Открыть…», файловый диалог за `IArchivePicker`,
   `DecodeToEntries` в фоне (`Task.Run`), обработка `Ok`/`NotSupported`/`InvalidData`.
4. **Браузер**: таблица содержимого (значок/имя/размер/тип) + навигация по папкам
   (вход двойным кликом, «Вверх», текущий путь).
5. **Пароль**: модальный диалог `PasswordWindow` + `IPasswordPrompt`; открытие
   зашифрованных архивов (**AES и ГОСТ** — расшифровка определяется автоматически по
   архиву), повтор при неверном пароле, отмена.

Покрытие: 16 тестов `MainViewModel` (открытие/навигация/пароль), в т.ч. сквозной путь
через ГОСТ-архив, собранный нашим writer-ом.

## Границы и ограничения

- v1 — только **чтение/просмотр**; извлечение на диск и создание архивов пока не входят.
- Чтение **в память**: `DecodeToEntries` декодирует всё содержимое целиком — для больших
  архивов тяжело; потоковое API в ядре — будущая доработка.
- Сессия не сохраняется (нет «недавних»/«открыть последний») — на будущее.
- Многоколоночный `DataGrid` не используется (пакет несовместим под Avalonia 12) —
  таблица собрана на `ListBox` + строка-заголовок.
- **Пароль vs неподдержка:** `DecodeToEntries` без пароля возвращает один и тот же
  `NotSupported` и для «нужен пароль», и для «неподдерживаемая возможность». Поэтому на
  неподдерживаемом (незашифрованном) архиве UI может зря показать диалог пароля. Различить
  их без доработки ядра нельзя. После принятого пароля `NotSupported` трактуется как
  неподдерживаемая возможность (а не неверный пароль) — сообщение это отражает.
- **AES + BCJ2 не поддерживается ядром:** архивы с `.exe`/бинарниками под AES (7-Zip
  включает фильтр BCJ2) не открываются — см. [`STAGE15_AES_STATUS.md`](STAGE15_AES_STATUS.md).
  Обычные AES+LZMA2 и ГОСТ-архивы открываются штатно.
