# План работ

## Текущий статус

Этапы 1, 1.5 и 1.6 завершены.

Текущий основной следующий этап — этап 2: encoder / writer.

Цель этапа 1 была довести управляемый декодер / распаковщик 7z до надёжного состояния для поддерживаемого подмножества формата без AES.

На этапе 1.5 реализован decoder-path для AES и зашифрованных 7z-архивов.

На этапе 1.6 реализован экспериментальный decoder-only путь для GOST Kuznyechik CTR direct-key.

Основной объём тестовой стабилизации `SevenZipFolderDecoder` уже выполнен. Дальше новые синтетические тесты добавляются только при наличии конкретного риска, а не ради полного перебора всех искусственных комбинаций.

Ближайшие крупные направления:

- этап 2: writer / encoder;
- постепенная замена временных внешних codec-зависимостей собственными реализациями;
- позднее развитие экспериментальной GOST-ветки после завершения основных этапов проекта.

## Этап 1: декодер / распаковка 7z без AES

### Цель

Сделать надёжный управляемый декодер, который умеет разбирать и распаковывать поддерживаемые архивы 7z без AES.

### Входит в этап

- `SevenZipArchiveReader`;
- `SevenZipArchiveDecoder`;
- `SevenZipEncodedHeaderDecoder`;
- `SevenZipFolderDecoder`;
- разбор `StreamsInfo`;
- разбор `FilesInfo`;
- разбор encoded header для поддерживаемых сценариев без шифрования;
- декодирование поддерживаемых методов и фильтров 7z без AES;
- восстановление файловой структуры архива;
- безопасная распаковка на диск;
- тесты на синтетических сценариях;
- тесты на реальных архивах;
- явные `NotSupported`-сценарии для неподдерживаемых возможностей;
- актуальная документация по состоянию проекта.

### Поддерживаемые методы и фильтры этапа 1

В кодовой базе уже присутствует поддержка:

- `Copy`;
- `LZMA`;
- `LZMA2`;
- `Delta`;
- `Swap2`;
- `Swap4`;
- BCJ-фильтров:
  - `x86`;
  - `ARM`;
  - `ARMT`;
  - `ARM64`;
  - `PPC`;
  - `SPARC`;
  - `IA64`;
- `BCJ2`;
- `BZip2`;
- `PPMd`;
- `Deflate`;
- `Deflate64`.

### Не входит в этап

- AES-шифрованные архивы;
- зашифрованные заголовки;
- production-ready энкодер;
- тяжёлая оптимизация;
- приложение / UI.

### Критерий завершения

Этап 1 можно закрывать, когда:

- полный набор тестов проходит;
- `README.md` и документы в `docs/` согласованы между собой;
- из документации очевидно, что AES остаётся вне этапа 1 и перенесён в отдельный этап 1.5;
- покрытие поддерживаемых веток декодирования зафиксировано тестами;
- оставшиеся ограничения явно описаны;
- в репозитории нет устаревших формулировок, которые искажают текущее состояние проекта.

## Этап 1.5: AES и зашифрованные 7z-архивы

### Статус

Этап завершён на ветке `stage15-aes`.

Реализован decoder-path для основных AES-сценариев 7z:

- AES packed streams;
- AES + Copy;
- AES + LZMA2;
- архивы без шифрования заголовков;
- архивы с зашифрованными заголовками;
- single-file архивы;
- multi-file архивы;
- solid multi-file архивы;
- распаковка на диск через `ExtractToDirectory`.

Реализация покрыта unit-тестами, synthetic archive-level тестами и real-archive тестами, созданными через настоящий `7z`.

### Цель

Добавить поддержку AES-сценариев 7z как отдельное расширение декодера после закрытия базового этапа 1.

AES не должен блокировать завершение этапа 1, потому что это отдельный слой поверх уже стабилизированного чтения структуры архива, декодирования folder-ов и безопасной распаковки.

### Входит в этап

- распознавание AES coder-а в 7z;
- разбор свойств AES coder-а;
- получение пароля через явный API;
- парольный материал UTF-16LE без BOM;
- direct key derivation для `NumCyclesPower == 0x3F`;
- SHA-256 key derivation для поддерживаемых `NumCyclesPower`;
- построение IV из AES properties;
- расшифровка packed stream-ов через AES-256-CBC;
- поддержка AES в `SevenZipFolderDecoder`;
- передача `SevenZipDecodeOptions` через основные decode/extract API;
- поддержка зашифрованных заголовков;
- корректные контракты ошибок для сценариев:
  - пароль не передан;
  - пароль неверный;
  - данные повреждены;
  - AES-сценарий пока не поддержан полностью;
- тесты на реальных AES-архивах;
- negative-тесты на неверный пароль, повреждённые данные и отсутствующий пароль;
- проверка, что ошибки AES не приводят к небезопасной записи на диск.

### Не входит в этап

- запись зашифрованных 7z-архивов;
- UI для ввода пароля;
- хранение паролей;
- интеграция с системными хранилищами секретов;
- streaming decrypt API;
- оптимизация derivation для больших `NumCyclesPower`;
- собственная реализация AES.

### Итог

Этап 1.5 закрыт после полного зелёного прогона тестов и финальной сверки ветки `stage15-aes`.

Зафиксировано:

- AES decoder-path реализован для поддерживаемых сценариев чтения 7z;
- encrypted packed streams поддержаны;
- encrypted header поддержан для покрытых real-archive сценариев;
- пароль передаётся через `SevenZipDecodeOptions`;
- отсутствие пароля возвращает `NotSupported`;
- неверный пароль возвращает `InvalidData`;
- ошибки AES не создают файлов и директорий при `ExtractToDirectory`;
- real-archive тесты покрывают `mhe=off` и `mhe=on`;
- real-archive тесты покрывают single-file, multi-file и solid multi-file сценарии.

## Этап 1.6 — экспериментальный GOST decoder-path

Статус: завершён.

На этапе реализован decoder-only путь для экспериментального GOST-расширения LzmaSharp.

Входит:

- Kuznyechik;
- CTR;
- IV;
- direct-key KDF;
- расшифровка packed stream-ов;
- поддержка зашифрованных заголовков;
- archive-level интеграция;
- synthetic-тесты для поддержанных и неподдержанных сценариев.

Не входит:

- Magma decrypt;
- полноценный KDF через Стрибог;
- другие GOST-сценарии;
- совместимость со стандартным 7-Zip;
- запись GOST-архивов.

Magma, полноценный KDF через Стрибог и остальные GOST-сценарии относятся к позднему развитию после завершения основных этапов проекта.

## Этап 2 — encoder / writer

Статус: следующий основной этап.

Цель этапа — начать реализацию записи данных:

- LZMA encoder;
- LZMA2 encoder;
- базовый 7z writer;
- минимальный набор тестов на round-trip.

Шифрование, GOST writer и расширенные криптографические сценарии не входят в базовый объём этапа 2.

### Основные направления

- усилить и расширить энкодер `LZMA`;
- усилить и расширить энкодер `LZMA2`;
- реализовать путь записи архивов 7z;
- добавить тесты совместимости в обе стороны:
  - наше кодирование -> декодирование эталонной реализацией;
  - эталонное кодирование -> декодирование нашей реализацией;
  - roundtrip внутри собственных компонентов проекта.

### AES при записи архивов

Запись зашифрованных 7z-архивов не является обязательной частью первого шага энкодера.

После появления базового writer-а её можно вынести в отдельный подпункт этапа 2 или в самостоятельный последующий этап. Это решение принимается после стабилизации обычной записи архивов.

### Важное замечание

В репозитории уже есть задел под энкодер и тестовые вспомогательные части.

Этап 2 не считается завершённым, пока кодирование не станет production-ориентированным, а не только test-oriented.

## Этап 3: оптимизация

### Условие старта

Оптимизация начинается только после функциональной стабилизации этапов 1 и 2.

Порядок фиксированный:

1. корректность;
2. тесты;
3. профилирование;
4. точечная оптимизация.

### Основные направления

- алгоритмические улучшения;
- снижение лишних аллокаций;
- пуллинг буферов;
- улучшение раскладки данных;
- `Span` / `ReadOnlySpan` / `Memory` там, где это даёт измеримую пользу;
- stream-friendly API там, где это реально улучшает сценарии использования;
- SIMD / intrinsics только после подтверждения профилированием;
- точечная оптимизация hot path без ухудшения читаемости публичной логики.
