# План работ

## Этап 0: Инфраструктура

Уже выполненная базовая работа:

- структура репозитория;
- настройка solution и проектов;
- базовая сборка и запуск тестов;
- начальная документация;
- эталонные исходники в `vendor/lzma-sdk`.

## Этап 1: Декодер / распаковка 7z (текущий этап)

Цель:

Сделать надёжный управляемый декодер, который умеет разбирать и распаковывать поддерживаемые архивы 7z без AES.

Основные задачи:

- завершить покрытие совместимости 7z;
- продолжать декодер маленькими шагами и через тесты;
- корректно валидировать структуру архива и топологию потоков;
- усилить безопасность распаковки;
- привести документацию в соответствие с реальным состоянием репозитория.

Что входит в этап 1:

- `SevenZipArchiveReader`;
- `SevenZipArchiveDecoder`;
- `SevenZipFolderDecoder`;
- поддержка уже реализованных методов и фильтров 7z;
- интеграционные тесты и тесты на реальных архивах;
- очистка устаревших названий, комментариев и описаний тестов.

Что явно не входит в этап 1:

- AES-шифрованные архивы;
- зашифрованные заголовки;
- UI / приложение;
- агрессивная оптимизация.

## Этап 2: Энкодер

Цель:

Пошагово реализовать собственный контур кодирования проекта.

Ожидаемый объём:

- более сильный энкодер `LZMA`;
- более сильный энкодер `LZMA2`;
- позднее — путь записи архивов 7z;
- проверки совместимости в обе стороны.

Важное замечание:

В репозитории уже есть задел под энкодер и тестовые вспомогательные части, но этап 2 не считается завершённым, пока кодирование не станет production-ориентированным, а не только test-oriented.

## Этап 3: Оптимизация

Только после функциональной стабилизации этапов 1 и 2.

Основные направления:

- алгоритмические улучшения;
- улучшение раскладки данных и снижение аллокаций;
- пуллинг буферов;
- `Span<T>` / `ReadOnlySpan<T>` / инкрементальные API;
- SIMD / intrinsics;
- при подтверждении профилированием — точечные низкоуровневые hot path оптимизации.

## Этап 4: Прикладной слой

Возможные направления после стабилизации ядра:

- desktop-приложение;
- CLI;
- benchmark-проект;
- расширение платформенной поддержки.

## Временные управляемые зависимости

Допустимы только там, где помогают закрыть реальный сценарий декодирования маленьким проверяемым шагом.

Текущие временные использования:

- `SharpZipLib` для декодирования `BZip2`;
- `SharpCompress` для отдельных методов 7z, например `PPMd` и `Deflate64`.

Долгосрочный план:

- заменить временные внешние декодеры собственными реализациями проекта;
- при замене сохранять внешнее поведение и стабильность тестов.
