# Статус этапа 1.6 — экспериментальная GOST-ветка

Этап 1.6 завершён.

На этапе добавлен decoder-path для экспериментальных GOST coder-ов LzmaSharp внутри 7z-контейнера.

> **Примечание.** Разделы ниже фиксируют состояние на момент закрытия этапа 1.6
> (decoder-only). GOST-ветка с тех пор развита значительно дальше — актуальный срез
> и проектные решения см. в разделе [«Обновление: развитие GOST после этапа 1.6»](#обновление-развитие-gost-после-этапа-16).

## Обновление: развитие GOST после этапа 1.6

После закрытия этапа 1.6 GOST-ветка доведена существенно дальше. Кратко, что сделано
(каждый примитив сверен с официальными тест-векторами соответствующего стандарта):

- **Magma**: блочный шифр (RFC 8891) и Magma-CTR (ГОСТ Р 34.13-2015) — сверены
  официальными векторами; Magma подключена в decryptor (больше не `NotSupported`).
- **Стрибог** (ГОСТ Р 34.11-2012, RFC 6986): хеш 512/256 — сверен векторами M1/M2.
- **HMAC-Стрибог и KDF_GOSTR3411_2012_256** (RFC 7836) — сверены векторами Appendix B.
- **Парольный KDF через Стрибог-256**: итеративная конструкция в стиле 7z AES
  (`SevenZipGostKeyDerivation.TryDeriveStribogKey`). Это собственная 7z-специфичная
  конструкция (официального вектора у неё нет), проверяется сверкой малых раундов с
  прямым `Стрибог-256` и end-to-end round-trip-ом.
- **GOST writer** (`SevenZipArchiveWriter.BuildGostEncryptedArchive`): создание
  ГОСТ-зашифрованных архивов — Кузнечик и Магма, режим только-шифрование и цепочка
  LZMA2 → ГОСТ (сжатие + шифрование), несколько файлов в архиве (свой IV на поток),
  криптослучайные соль/IV по умолчанию.

Граница неизменна: формат остаётся **внутренним экспериментальным** и не совместим
со стандартным 7-Zip (закрытые private method id проекта).

### Лимит числа циклов формирования ключа (numCyclesPower)

Парольный KDF поддерживает `numCyclesPower` в диапазоне `0..SupportedNumCyclesPowerMax`
(сейчас **20**) либо специальное значение `DirectKeyNumCyclesPower = 0x3F` (тестовый
direct-key). Это **осознанное и задокументированное ограничение**, а не недоработка.

**Природа лимита — память, а не криптография.** Парольный KDF хеширует конкатенацию
всех `2^numCyclesPower` раундов одним вызовом `Стрибог-256`, поэтому объём временного
буфера равен `2^numCyclesPower × (соль + пароль + 8)` байт. При `p = 20` это порядка
десятков мегабайт; рост экспоненциальный. Сам стандарт ГОСТ и сверенный по официальным
векторам примитив Стрибога никаких ограничений на число раундов не накладывают — предел
введён исключительно для удержания памяти в разумных рамках.

**Изменяемость.** Лимит сосредоточен в одной константе
`SevenZipGostCoder.SupportedNumCyclesPowerMax`; на неё опираются `IsSupportedNumCyclesPower`,
парольный KDF, encryptor и decryptor. Поднятие лимита **обратно совместимо**: всё, что
читалось раньше, продолжает читаться, добавляется лишь поддержка более высоких `p`.
Примитив Стрибога и его валидация при этом не затрагиваются.

**Пути повышения, если этого потребуют надзорные органы** (от простого к полному):

1. **Поднять константу** `SupportedNumCyclesPowerMax` (например, до 22–24). Минимальная
   правка; цена — больший временный буфер на операцию формирования ключа.
2. **KDF с ограниченной памятью**: прогон Стрибога по «виртуальному» сообщению блоками
   (без удержания полного буфера). Снимает практический потолок полностью, не меняя ядро
   Стрибога; добавляемый второй путь обязателен к diff-тестированию против one-shot.
3. **Подгонка под конкретное требование**: если регулятор укажет точное число циклов —
   значение выставляется прямо под него.

Любой из путей — это локальная правка в пределах GOST-модуля с добавлением тестов, без
риска для уже сверенной с эталоном криптографии.

## Границы этапа

GOST-поддержка является внутренним экспериментальным расширением LzmaSharp.

Она не совместима со стандартным 7-Zip и использует закрытые private method id проекта.

В этап входит только чтение и декодирование архивов.

В этап не входит:

- запись GOST-архивов;
- совместимость со стандартным 7-Zip;
- Magma decrypt;
- полноценный GOST KDF через Стрибог;
- UI для ввода пароля;
- хранение паролей;
- streaming decrypt API.

## Реализовано

- распознавание экспериментальных GOST method id;
- отдельные private method id для Kuznyechik и Magma;
- разбор GOST properties версии 1;
- проверка версии properties;
- проверка flags;
- проверка размеров salt и IV;
- direct-key KDF через `NumCyclesPower == 0x3F`;
- построение IV для Kuznyechik CTR;
- Kuznyechik block cipher;
- Kuznyechik CTR transform;
- расшифровка packed stream через Kuznyechik CTR;
- подключение GOST decrypt в `SevenZipFolderDecoder`;
- поддержка GOST на archive-level API;
- поддержка GOST encrypted header в decoder-path.

## Зафиксированные ограничения

### Kuznyechik

Поддержан только сценарий:

- Kuznyechik;
- CTR;
- IV размером 8 байт;
- direct-key режим;
- decoder-only.

### Magma

> Срез этапа 1.6. Актуально: Magma decrypt и Magma-CTR реализованы и сверены
> официальными векторами — см. раздел «Обновление».

Magma method id распознаётся, но сам decrypt не реализован.

Результат для Magma:

- `NotSupported`.

### KDF

> Срез этапа 1.6. Актуально: парольный KDF через Стрибог-256 реализован
> (`numCyclesPower` в диапазоне `0..SupportedNumCyclesPowerMax`) — см. раздел
> «Обновление» и подраздел про лимит numCyclesPower.

Поддержан только direct-key режим.

Любой другой `NumCyclesPower` сейчас возвращает:

- `NotSupported`.

Полноценная парольная функция формирования ключа через Стрибог не реализована.

## Контракт ошибок

Для GOST-сценариев используется общий pattern result enum:

- `Ok` — данные успешно расшифрованы и декодированы;
- `InvalidData` — некорректные properties, IV, method id или результат расшифровки;
- `NotSupported` — сценарий распознан, но не входит в текущую поддержку.

Отсутствующий пароль для GOST-сценария возвращает `NotSupported`.

Неверный пароль фиксируется как `InvalidData`.

## Итог

Этап 1.6 закрывает экспериментальный decoder-only путь для GOST Kuznyechik CTR direct-key.
