# План тестирования

## Текущее состояние

Репозиторий уже давно вышел за пределы старого состояния «два smoke-теста».

Сейчас тесты покрывают:

- `Checksums`;
- `Lzma1`;
- `Lzma2`;
- `SevenZip`.

Зона `SevenZip` уже включает:

- тесты парсинга;
- тесты CRC и метаданных;
- сценарии с пустыми потоками и подпотоками;
- сценарии с несколькими folder и pack stream;
- тесты безопасности распаковки;
- интеграционные тесты цепочек coder;
- тесты на реальных `.7z`-архивах для нескольких методов и комбинаций фильтров;
- явные `NotSupported`-сценарии для архивов, связанных с AES.

Фреймворк: `xUnit`.

## Цель тестирования на этапе 1

К концу этапа 1 каждый поддерживаемый путь декодирования 7z должен быть закреплён тестами хотя бы на одном из уровней:

- unit-тест;
- интеграционный тест;
- тест на реальном архиве.

## Ближайшие задачи по тестам

### 1. Построить карту покрытия для `SevenZipFolderDecoder`

Нужно вести явную карту вида:

- ветка декодера / метод / фильтр;
- соответствующий тест или набор тестов.

Это самый быстрый способ увидеть, чего действительно не хватает, а что просто плохо названо.

### 2. Убрать устаревшие названия, которые скрывают реальное покрытие

В репозитории уже есть тесты, чьи имена или комментарии больше не соответствуют их фактическим ассертам.

Такие тесты нужно переименовывать сразу, чтобы дерево оставалось понятным после долгой паузы.

### 3. Закрыть очевидные прямые пробелы по веткам

Если ветка метода или фильтра существует в `SevenZipFolderDecoder`, у неё должен быть хотя бы один очевидный прямой тест либо явно задокументированный интеграционный / real-archive тест, который её покрывает.

При первом проходе стоит отдельно проверить покрытие веток для:

- `Swap2`;
- `Swap4`;
- `Delta`;
- каждого фильтра семейства BCJ;
- `BCJ2`;
- `BZip2`;
- `PPMd`;
- `Deflate`;
- `Deflate64`.

### 4. Сохранять явные out-of-scope тесты для этапа 1

AES и зашифрованные заголовки осознанно не входят в этап 1.

Это должно оставаться видимым в тестах через явные `NotSupported`-сценарии, а не через молчаливое отсутствие.

## Какие области покрытия SevenZip должны оставаться видимыми в дереве тестов

В дереве тестов и дальше должно быть легко найти такие группы:

- корректность archive reader;
- обработка encoded header;
- поведение folder decoder;
- поведение archive decoder;
- безопасность распаковки;
- совместимость на реальных архивах;
- неподдерживаемые, но явно отслеживаемые сценарии.

## Правила добавления тестов

- Одно маленькое изменение -> один соответствующий маленький тест.
- По возможности предпочитать понятные синтетические фикстуры огромным непрозрачным бинарникам.
- Реальные `.7z`-файлы использовать там, где важна совместимость на уровне контейнера.
- Если имя теста перестало соответствовать коду, переименовывать его сразу.

## После этапа 1

Когда начнётся этап 2, нужно завести отдельный план тестирования энкодера:

- наше кодирование -> декодирование эталонной реализацией;
- эталонное кодирование -> декодирование нашей реализацией;
- roundtrip внутри собственных компонентов проекта;
- профилирование размера и скорости только после функциональной стабилизации.
