# C# Cleanup

## Назначение

Очистить существующий C#-код без изменения поведения, публичного API, форматов данных, криптографической семантики и файловых транзакций.

Перед аудитом или выполнением batch-а прочитай и соблюдай
[правила минималистичного стиля](docs/minimal-style.md).

Эти правила применяются только в рамках активированного skill
`csharp-cleanup` и только к файлам утверждённого batch-а.
Они не являются разрешением на очистку соседнего кода.

## Запрещённый режим

Не выполняй аудит и очистку всего репозитория в одной непрерывной задаче.

Не:

- редактируй весь репозиторий сразу;
- запускай массовое автоформатирование;
- объединяй несколько категорий очистки в один batch;
- удаляй пакеты только по отсутствию текстового упоминания;
- начинай следующий batch без завершённой проверки предыдущего;
- создавай субагентов для параллельного редактирования одних файлов;
- меняй поведение, тестовые ожидания или публичный API;
- исправляй найденные функциональные дефекты в рамках style-cleanup.

## Фаза 1. Только аудит

Сначала проверь чистоту рабочей копии:

```text
git status --short
```

Если рабочая копия не чистая и изменения не были явно разрешены, остановись.

Проведи read-only аудит и классифицируй замечания:

- `U`: неиспользуемые, дублирующие или глобально доступные `using`;
- `B`: лишние фигурные скобки вокруг одного простого оператора;
- `C`: избыточные явные приведения и скобки выражений;
- `V`: лишние временные переменные, тривиальные wrappers/helpers и комментарии-пересказы;
- `P`: потенциально лишние `PackageReference` или зависимости.

Не редактируй код в фазе аудита.

## План batch-ей

Разбей работу на атомарные batch-и.

Один batch:

- только одна категория (`U`, `B`, `C`, `V` или `P`);
- не более трёх файлов;
- ориентир — не более 80 изменённых строк;
- один затронутый проект;
- один независимый критерий проверки.

Для каждого batch укажи:

1. ID;
2. категорию;
3. точные файлы;
4. точные места;
5. предлагаемое преобразование;
6. почему поведение не изменится;
7. требуемую сборку;
8. целевые тесты;
9. риск;
10. рекомендуемый русский заголовок коммита.

Категория `P` всегда выполняется отдельной веткой и отдельным коммитом.

## Фаза 2. Выполнение одного batch

В одной задаче выполняй ровно один заранее утверждённый batch.

Перед правкой:

1. `git status --short`;
2. прочитай только файлы batch-а и минимально необходимые конфигурационные файлы;
3. проверь `.editorconfig`, `GlobalUsings.cs`, `Directory.Build.props`, `Directory.Packages.props` и релевантный `.csproj` только если это необходимо категории.

После правки:

1. `git diff --check`;
2. `git diff --name-only`;
3. проверь allowlist файлов;
4. собери затронутый проект;
5. запусти целевые тесты;
6. покажи diff;
7. остановись.

Допускается максимум два цикла исправления одной и той же проблемы.

Каждый цикл:

1. определить точную причину;
2. внести одно минимальное изменение;
3. повторить минимальную относящуюся к проблеме проверку.

После второго неуспешного цикла остановиться со статусом `BLOCKED`.
Не начинать batch заново и не переписывать его с нуля.

## Особые правила удаления пакетов

Пакет нельзя считать неиспользуемым только потому, что его namespace не найден в `.cs`.

До удаления установи:

- где он объявлен;
- используется ли централизованное управление версиями;
- участвует ли он как analyzer/source generator;
- добавляет ли build targets/props;
- нужен ли он runtime/reflection-коду;
- используется ли он тестами или interoperability-проверками;
- не приходит ли нужный API через transitive dependency, которую нельзя считать контрактом.

После удаления обязательны:

- `dotnet restore`;
- сборка затронутого проекта;
- целевые тесты;
- полный тестовый проект;
- проверка lock/assets-файлов, если они отслеживаются.

## Финальный отчёт batch-а

Коротко укажи:

1. ID batch-а;
2. изменённые файлы;
3. выполненные упрощения;
4. обоснование, почему преобразования не должны менять поведение, и перечень выполненных проверок;
5. команды и exit codes;
6. тесты;
7. `git diff --name-only`;
8. оставшиеся замечания;
9. commit не создан.

Заверши:

`DONE`

или

`BLOCKED`
