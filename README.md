# LzmaSharp

Управляемая реализация на C# для семейства алгоритмов LZMA / LZMA2 и обработки контейнера 7z.

## Текущий этап

**Этап 1.6 завершён.**

Проект доведён до состояния надёжного управляемого decoder-only распаковщика 7z для поддерживаемого подмножества формата.

Завершены:

- этап 1 — базовый decoder-path без AES;
- этап 1.5 — AES / 7zAES decoder-path;
- этап 1.6 — экспериментальный GOST decoder-path.

GOST-поддержка является экспериментальным расширением LzmaSharp, использует private method id и не совместима со стандартным 7-Zip.

## Принципы разработки

- Работаем маленькими, проверяемыми шагами.
- Сначала корректность и тесты, потом оптимизация.
- Код должен быть понятным и честным C# без скрытой магии.
- Комментарии, XML-документация и заголовки коммитов пишутся на русском языке.
- Основная логика остаётся управляемой и читаемой.
- Низкоуровневая оптимизация — отдельный поздний этап.

### Безопасность распаковки

Контур распаковки валидирует пути вывода до записи на диск.

Распаковщик отклоняет:

- небезопасные пути;
- абсолютные пути из архива;
- попытки выхода за пределы целевой директории;
- конфликтующие варианты структуры вывода;
- зарезервированные имена Windows;
- недопустимые имена и варианты путей, которые могут привести к небезопасной записи.

## Временные внешние зависимости

На текущем этапе проект допускает узкие управляемые зависимости для отдельных методов 7z, чтобы закрывать реальные сценарии декодирования маленькими проверяемыми шагами.

Текущие зависимости в `Lzma.Core`:

- `SharpZipLib` — временная поддержка декодирования `BZip2`;
- `SharpCompress` — временная поддержка отдельных методов 7z, например `PPMd` и `Deflate64`.

Долгосрочное направление не меняется: критичные кодеки и логика контейнера должны постепенно переходить на собственные реализации проекта.

## Текущая поддержка AES

На этапе 1.5 реализован decoder-path для AES-сценариев 7z.

Поддержано:

- распознавание 7zAES coder-а;
- разбор свойств AES coder-а;
- парольный материал в UTF-16LE без BOM;
- direct key derivation для `NumCyclesPower == 0x3F`;
- обычный SHA-256 key derivation для поддерживаемых `NumCyclesPower`;
- построение IV из AES properties;
- AES-256-CBC расшифровка packed stream-ов;
- передача пароля через `SevenZipDecodeOptions`;
- чтение AES-архивов без шифрования заголовков;
- чтение AES-архивов с зашифрованными заголовками;
- декодирование и распаковка AES-архивов через верхние API.

Покрыты реальные 7z-сценарии:

- `mhe=off`, single-file, `AES + Copy`;
- `mhe=off`, single-file, `AES + LZMA2`;
- `mhe=off`, multi-file, `AES + LZMA2`;
- `mhe=off`, solid multi-file, `AES + LZMA2`;
- `mhe=on`, single-file, `AES + LZMA2`;
- `mhe=on`, multi-file, `AES + LZMA2`;
- `mhe=on`, solid multi-file, `AES + LZMA2`.

Пока не входит:

- запись AES-архивов;
- UI для ввода пароля;
- хранение паролей;
- интеграция с системными хранилищами секретов;
- streaming decrypt API;
- оптимизация derivation для больших `NumCyclesPower`;
- собственная реализация AES.

## Текущая поддержка GOST

На этапе 1.6 реализован экспериментальный decoder-path для GOST-сценариев LzmaSharp внутри 7z-контейнера.

GOST-поддержка является внутренним расширением проекта:

- использует private method id;
- не совместима со стандартным 7-Zip;
- поддерживает только чтение и декодирование;
- не реализует запись архивов.

Поддержано:

- распознавание экспериментальных GOST coder-ов;
- Kuznyechik;
- CTR;
- IV;
- direct-key KDF для `NumCyclesPower == 0x3F`;
- расшифровка packed stream-ов через Kuznyechik CTR;
- подключение GOST decrypt в decoder-path 7z;
- поддержка GOST encrypted header;
- archive-level интеграция.

Покрыты synthetic-сценарии:

- `GOST Kuznyechik + Copy`;
- `GOST Kuznyechik + LZMA2`;
- single coder;
- encrypted header;
- encrypted header + encrypted file;
- no password;
- wrong password;
- invalid properties;
- unsupported KDF;
- Magma как `NotSupported`.

Пока не входит:

- Magma decrypt;
- полноценный KDF через Стрибог;
- другие GOST-сценарии;
- совместимость со стандартным 7-Zip;
- запись GOST-архивов;
- UI для ввода пароля;
- хранение паролей;
- streaming decrypt API.

Magma, полноценный KDF через Стрибог и другие GOST-сценарии относятся к позднему развитию после завершения основных этапов проекта.

Подробный контракт этапа описан в [`docs/STAGE16_GOST_STATUS.md`](docs/STAGE16_GOST_STATUS.md).

## Границы этапов

### Этап 1

Довести декодер до состояния, когда он надёжно распаковывает поддерживаемые архивы 7z без AES.

Входит в этап:

- корректность парсинга;
- корректность декодирования;
- покрытие реальными архивами;
- безопасность распаковки;
- приведение репозитория и документации в аккуратное состояние.

Не входит в этап:

- AES / зашифрованные архивы 7z;
- production-ready энкодер;
- тяжёлая оптимизация;
- приложение / UI.

Реализовано:

- API для передачи пароля через `SevenZipDecodeOptions`;

## Дальнейшее направление

Кроме прикладного слоя и возможного расширения на другие платформы, на поздних этапах планируется постепенно заменить временные внешние зависимости собственными управляемыми реализациями.

В первую очередь это касается:

- `PPMd`;
- `BZip2`;
- `Deflate`;
- `Deflate64`;
- возможной поддержки ZIP-совместимых сценариев.

Цель — не тянуть сторонние библиотеки ради этих алгоритмов и постепенно перевести критичную логику кодеков внутрь проекта.

Отдельным поздним направлением остаётся расширение экспериментальной GOST-ветки.

К нему относятся:

- Magma decrypt;
- полноценный KDF через Стрибог;
- дополнительные GOST-сценарии.

Эти работы не входят в основные этапы и будут рассматриваться после стабилизации базового decoder/writer/optimization roadmap.
