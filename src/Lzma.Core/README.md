# Ti-Soft.LzmaSharp

Чисто **управляемая** (100% managed C#, **без нативных зависимостей**, без `unsafe`, без P/Invoke)
реализация 7-Zip/LZMA для .NET. Ядро архитектурно переносимо между платформами .NET;
release matrix на данном коммите: CI-матрица ОС (ubuntu/windows/macos) добавлена в `e04c90e`
и прогнана (см. `.github/workflows/ci.yml`): сборка Release и тесты зелёные на всех трёх ОС
(run `38794891354`, HEAD `be413de`: `ubuntu-latest`, `windows-latest`, `macos-latest` — success).
Первый прогон матрицы дал 4 падения на `ubuntu-latest`/`macos-latest`; причина — платформенно-
зависимые входные данные тестов и инъекция отказа, работавшая только на Windows, — устранена.
Локально на Windows полный прогон зелёный — 1925 тестов. Interop-проверки с внешним 7-Zip в CI
по-прежнему фактически не выполняются (7-Zip на раннерах не установлен). Android/iOS
считаются поддерживаемыми только после появления build/publish/AOT/runtime smoke-задач.

В отличие от большинства решений в экосистеме, это **не обёртка над `7z.dll`** и умеет не только
читать, но и **писать** `.7z` — совместимо с настоящим 7-Zip (проверено интеропом на машине
с установленным 7-Zip; в CI interop-проверки фактически не выполняются — см. `docs/SDL.md` §3).

## Возможности

- **Чтение и запись `.7z`.**
- Кодеки: **LZMA**, **LZMA2**, **PPMd** (var.H), фильтр **BCJ2** (плотное сжатие `.exe`/`.dll`),
  `Copy`, а также на чтение — Delta/Swap, BCJ (x86/ARM/ARM64/…), BZip2, Deflate/Deflate64.
- **Шифрование 7zAES** (AES-256) на чтение и запись.
- Экспериментальная поддержка **ГОСТ**.
- **Многотомные** архивы (`.7z.001/.002/…`).
- Потоковые API для файлов и архивов **больше 2 ГиБ** (архив читается по частям; см. ограничения памяти
ниже для отдельных entry).
- Автовыбор кодека по содержимому (текст → PPMd, `.exe` → BCJ2, несжимаемое → store).
- **ZIP** — базовое чтение/запись/распаковка (см. ограничения ниже).

## ZIP

Поддерживается **чтение и запись** `.zip`:

- Методы сжатия: **Store (0)** и **Deflate (8)** — собственный управляемый Deflate.
- **ZIP64** — архивы больше 4 ГиБ и/или с более чем 65535 записями (потоковый путь).
- **Потоковость** — потоковое чтение каталога и создание ZIP; извлечение по пути **без загрузки
  всего архива в память** (поддержка архивов больше 2 ГиБ). In-memory путь (`ZipReader`/`ZipWriter`)
  — до 2 ГиБ.
- **Извлечение через временный файл** — данные пишутся в `{имя}.{16 hex}.tmp` рядом с назначением,
  публикуются после успешной проверки и закрытия потока, а при отказе операция откатывается целиком:
  прежние байты перезаписываемых файлов восстанавливаются из backup (`{имя}.{16 hex}.bak`,
  создаётся переименованием). Остатки `.tmp`/`.bak` возможны при убийстве процесса; восстановление
  после обесточивания не гарантируется. 7z-маршрут использует тот же журнал стадии: folder
  публикуется после закрытия потоков и проверки результата, при отказе прежние байты
  восстанавливаются; перед первой записью данных проверяются свободное место и длина путей
  с учётом суффикса стадии (аддитивные значения `InsufficientSpace`/`PathTooLong`
  в `SevenZipArchiveDecodeResult`).
- **Проверка длины пути и расширенные пути Windows** — имя временного и backup-файла добавляет
  к полному пути 21 символ, поэтому до первой записи проверяется длина пути назначения, каталогов
  и имени стадии; при превышении возвращается `ZipExtractResult.PathTooLong` (значение добавлено
  аддитивно). Лимиты — принятая в реализации модель: Windows 32759 (расширенный предел 32767
  минус запас на префикс), macOS 1024, прочие POSIX 4096, компонент имени 255 на всех платформах;
  на POSIX длина измеряется в байтах UTF-8. На Windows файловые вызовы маршрута переводятся на
  расширенную форму `\\?\` (UNC — `\\?\UNC\`) при длине от 259 символов, поэтому
  длинные пути не зависят от opt-in хоста (`LongPathsEnabled` + `longPathAware`); короткие пути,
  относительные пути и другие ОС не затрагиваются. Ограничения: поведение на хосте с
  `LongPathsEnabled=0` подтверждено кодом и ревью, но не измерено; проверки конфликтов
  `HasFileOnPath`/`HasFileOnDirectoryPath` (общие для ZIP и 7z) с шага B5c переведены на
  расширенную форму — конфликт промежуточного сегмента на длинных путях распознаётся как
  `InvalidData` до первой мутации; единственным необёрнутым вызовом остаётся
  `File.SetAttributes` на пути перезаписи (до шага B6).
- **Проверка свободного места** — до первой записи ядро сравнивает сумму распакованных размеров
  со свободным местом тома назначения и при нехватке возвращает `ZipExtractResult.InsufficientSpace`
  (значение добавлено аддитивно, существующие коды не изменены). Оценка приближённая: без запаса
  и без учёта накладных расходов ФС. Измерение best-effort — если том не определён (UNC) или
  не готов, проверка пропускается и операция не блокируется. Потребитель, не распознающий новое
  значение, обязан трактовать любой результат, отличный от `Ok`, как отказ. Сообщение пользователю
  формирует вышестоящий слой: библиотека только возвращает состояние.

  Термин «потоковый» означает **потоковое чтение контейнера** (archive input streaming). Он **не
  гарантирует** bounded-memory для каждого entry. Отдельные entry могут буферизоваться целиком
  в зависимости от метода (см. ограничения WinZip-AES ниже).
- **Шифрование WinZip-AES (AES-256)** — открытие и создание зашифрованных ZIP по паролю; совместимо
  с 7-Zip/WinZip (потоковый путь).
- Параллельное сжатие по файлам (загрузка ядер).

Ограничения:

- Legacy **ZipCrypto** (традиционное PKWARE-шифрование) не поддержан — только WinZip-AES.
- **Ограничения WinZip-AES (шифрованные ZIP-члены):**
  - архив может быть открыт как поток;
  - один зашифрованный член **буферизуется целиком в памяти** при извлечении;
  - `CompressedSize > int.MaxValue` **отклоняется** как неподдерживаемый;
  - практический предел ниже `int.MaxValue` и зависит от доступной памяти и дополнительных буферов;
  - этот путь **не предназначен** для произвольно больших недоверенных членов.

## Быстрый старт

Распаковка `.7z` в память:

```csharp
using Lzma.Core.SevenZip;

byte[] archiveBytes = File.ReadAllBytes("data.7z");

if (SevenZipArchiveDecoder.DecodeToEntries(archiveBytes, out SevenZipDecodedEntry[] entries)
    == SevenZipArchiveDecodeResult.Ok)
{
    foreach (SevenZipDecodedEntry entry in entries)
        if (!entry.IsDirectory)
            Console.WriteLine($"{entry.Name}: {entry.Bytes.Length} байт");
}
```

Создание `.7z`:

```csharp
using Lzma.Core.SevenZip;

var entries = new[]
{
    new SevenZipArchiveWriterEntry("hello.txt", "Привет, мир!"u8.ToArray()),
};

if (SevenZipArchiveWriter.BuildArchive(entries, SevenZipWriterCompressionMethod.Lzma2, out byte[] archive)
    == SevenZipArchiveWriteResult.Ok)
{
    File.WriteAllBytes("out.7z", archive);
}
```

Извлечение прямо на диск (с проверкой путей и CRC):

```csharp
SevenZipArchiveDecoder.ExtractToDirectory(
    File.ReadAllBytes("data.7z"), SevenZipDecodeOptions.Default,
    destinationDirectory: "out", overwrite: false, out _);
```
